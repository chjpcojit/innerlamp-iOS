## Overview

"Sổ giỗ chạp" — the memorial book: a list of ancestors / relatives with their next death
anniversary (giỗ), and a form to add, edit or delete an entry. The list is reached from the
"Sổ giỗ" link beside "Lịch âm" in Home's week strip; `ILMemorialCoordinator` is a child of
`ILHomeCoordinator` and owns both screens (list → form). Data lives on the server (`/v1/memorials`) with a Core Data offline read cache; there
is no portrait sync (the API has no photo route). Spec: `Docs/Specs/Memorial/`.

## Navigation events

List (`ILMemorialNavEvent`):
- `.back` — pop and `finish()`.
- `.addEntry` — push the form in add mode (sticky bottom "Thêm người thân" button; the nav bar has no add action).
- `.editEntry(ILMemorialEntity)` — push the form for that entry (the entity is passed so the form needs no async load).
- `.openFamilyTree` — "Xem gia phả" ghost button under the list; the coordinator pushes `ILFamilyTreeCoordinator` as a child (see `Scenes/FamilyTree/`).

Form (`ILMemorialEditNavEvent`):
- `.back` — pop without saving.
- `.saved(message:)` / `.deleted(message:)` — pop, then the coordinator calls `ILMemorialViewModel.didFinishEditing(message:)` (reload + banner).

## Known gaps / not implemented yet

- Reminders: `scheduleReminders` / `cancelReminder` are TODO stubs — mechanism not confirmed
  (`TD-Memorial-001`, `AS-Memorial-002`). The reminder fields are stored, nothing is scheduled.
- "Thêm vào Lời nhắc" (Reminders) sync: not built (`TD-Memorial-001`).
- Portrait: placeholder avatar (initial letter) only; no picker/storage (`TD-Memorial-002`).
- No server sync — no API contract (`AS-Memorial-001`).
- Leap lunar months are skipped; delete has no confirmation (`AS-Memorial-003`, `AS-Memorial-004`).
- `ILLunarCalendar.solarToLunar` returns day 0 for 2054-05-07 (pre-existing); affects only that far-future date.
- No UI test — not requested.
