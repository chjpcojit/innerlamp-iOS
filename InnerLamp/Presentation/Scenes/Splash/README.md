## Overview

First screen the app shows — pure branding, no user interaction. Auto-advances after a fixed
delay to give the lamp breathe/flicker animation time to run. Owned top-level by
`AppCoordinator` (`start()` calls `showSplash()` before anything else); currently always routes
to `Onboarding` next (`isOnboardingCompleted()` check is stubbed out, see Known gaps).

## Navigation events

- `.goToOnboarding` — always fired today when the splash auto-advance timer elapses.
- `.goToMain` — reachable code path exists in `ILSplashCoordinator`/`AppCoordinator`, but
  `ILSplashViewModel.handleSplashFinished()` never sends it yet (see Known gaps).

## Known gaps / not implemented yet

- `handleSplashFinished()` always sends `.goToOnboarding` — the real
  `useCase.isOnboardingCompleted()` branch (→ `.goToMain` when onboarding is already done) is
  written but commented out. Left as-is since flipping it is a product decision, not something
  this pass should silently change.
- `ILSplashBrandBackdropView` (dark radial + top glow), `ILSplashAmbienceView` (ripple + ray),
  `ILSplashEmberFieldView`, `ILSplashWordmarkLabel` and the lamp breathe/flicker timing stay
  Splash-specific (`Presentation/Scenes/Splash/Views/`) rather than promoted to `DesignSystem` —
  visually similar treatments exist elsewhere (e.g. Onboarding's intro step) but aren't
  deduplicated against this one in this pass; only the truly generic pieces
  (`ILLampGlowView`, `ILLFlameView`, `ILLoadingDotsView`) were shared.
- `ILFlameView`'s `blur(6px)` stand-in: the `ilword` reveal fakes the CSS blur with a
  same-color `shadowRadius` ramp (UIKit has no animatable label blur), so the wordmark's
  "focus pull" reads slightly softer than the prototype.
- No UI test — not requested.
