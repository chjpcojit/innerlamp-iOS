## Overview

Edit Profile screen (prototype screen `edit`, "Chỉnh sửa hồ sơ"): a pushed child screen of the
"Tôi" tab, reached from the Profile header's "Sửa hồ sơ" pill (`ILProfileCoordinator`) and from the
account card on Settings (`ILSettingsCoordinator`). Layout top to bottom: `ILNavBar` with a "Lưu"
pill action; an 88pt initials avatar with a camera badge + "Đổi ảnh đại diện" link; four labeled
input cards (Pháp danh hoặc tên gọi, Số điện thoại (read-only), Chùa / đạo tràng, Đôi dòng về bạn
(multi-line serif)); "Hiển thị trong đạo tràng" group (3 value rows: Chuỗi ngày tinh tấn / Nhật ký
tu tập / Lịch sử cúng dường); "Vùng cẩn trọng" (Đổi mật khẩu, Xóa tài khoản và toàn bộ dữ liệu).
Design: prototype screen `edit` (`Docs/design_handoff_innerlamp/design/InnerLamp Prototype.dc.html`).
No spec under `Docs/Specs/EditProfile/` yet.

## Navigation events

- `goBack` — back chip tapped. Pops and finishes (unsaved edits are discarded, no confirm yet).
- `saved` — "Lưu" tapped, validation passed and `saveProfile` returned. Pops and finishes.
- `changeAvatar` — camera badge or "Đổi ảnh đại diện" tapped. TODO (photo picker/upload flow not designed).

## Known gaps / not implemented yet

- All data is mock (`ILEditProfileUseCaseImpl.getProfile()`), matching the prototype's `edit`
  screen ("Diệu Tâm" / DT). ⚠️ It does not match the Profile tab mock ("Nguyễn Bình An", pháp danh
  "Tâm Minh") — the prototype itself is inconsistent; both converge once a real profile API exists.
- The prototype merges name + dharma name into one field ("Pháp danh hoặc tên gọi"), while
  `ILProfileEntity` keeps `fullName` and `dharmaName` separately. ⚠️ Not confirmed how the single
  field maps to the backend.
- `saveProfile(_:)` is a TODO stub — tapping "Lưu" validates, then pops without persisting anything.
  Wire via data-builder once the update-profile contract is confirmed.
- ⚠️ Assumption: phone number is read-only (it is the login identity; changing it would need OTP
  re-verification). "Chùa / đạo tràng" is free text; it may become a picker of real sanghas.
- The only validation is "display name required" — no length limits are in the design.
- `BaseViewController`'s keyboard avoidance only tracks `UITextField`, so the multi-line bio
  (`UITextView`) is not auto-scrolled above the keyboard; `keyboardDismissMode = .interactive` lets
  the user drag it away. Fixing it belongs in `Core/Base` (out of scope for this skill).
- `ILNavBar` has no disabled state for its pill action — while saving, the whole header ignores
  touches instead.
- `ILAvatarView` draws a 1px tone border and uses Be Vietnam Pro initials; the prototype avatar is
  borderless with Lora initials.
