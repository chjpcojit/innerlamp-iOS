## Overview

Notifications screen (prototype screen `notif`, "Thông báo"): a pushed screen inside the "Tôi" tab
(owned by `ILProfileCoordinator`), reached via the Profile menu's "Thông báo" row. Shows a header
(serif title + "Đóng"), an always-dark "Sắp diễn ra" hero card with two pills ("Ngồi ngay" / "Bỏ
qua tối nay"), the "HÔM NAY" section eyebrow, and a list of notification rows (tinted icon tile,
title + relative time, body, unread dot). Design: prototype screen `notif`
(`Docs/design_handoff_innerlamp/`). No spec under `Docs/Specs/Notifications/` yet.

Note on naming: the feature/scene is "Notifications" (plural), but the core Domain entity is a
single `ILNotificationEntity` (+ `ILNotificationUpcomingEntity`), mirroring how `ILLibraryEntity`
aggregates `ILLibraryItemEntity` — there is no single "notifications" business object.

## Known gaps / not implemented yet

- All data is mock (`ILNotificationsUseCaseImpl`) — upcoming session and notification list need an
  API/push contract. `isRead` is static; there is no mark-as-read flow.
- Relative time is computed from `Date` via fixed thresholds ("vừa xong" / "N phút" / "N giờ" /
  "hôm qua" / "N ngày"); the prototype's exact 0.38/0.55 text alphas are normalized to the existing
  `inkMuted` (0.42) / `inkTertiary` (0.50) tokens.
- The offering row's glyph uses `Tone.ink` (`goldDeep`) — the prototype's `--il-link` also flips to
  a lighter gold in dark mode; this is a minor dark-mode fidelity gap.
- `.failure` renders nothing (no network-backed source yet).
