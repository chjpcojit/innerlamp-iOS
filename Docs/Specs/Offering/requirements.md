## User Story

As a practitioner, I want to make a lamp offering (cúng dường đèn) to a temple
and dedicate the merit, so that I can support the temple and receive a public
receipt.

## Acceptance Criteria (EARS notation)

### Offering

- WHEN the Offering screen loads, THE SYSTEM SHALL show the header ("Cúng dường
  đèn"), a dedication card ("Thắp một ngọn đèn, hồi hướng cho người thương" +
  "Bạn đã thắp 2 / 3 ngọn mùa Vu Lan"), and the amount options.
- WHEN the screen renders the amount options, THE SYSTEM SHALL offer three
  choices: 50.000đ (một ngọn), 200.000đ (bốn ngọn), and Tùy tâm (custom amount
  input).
- WHEN the user selects an amount, THE SYSTEM SHALL highlight it and update the
  payment button label to show the selected amount.
- WHEN the user enters a custom amount, THE SYSTEM SHALL accept a free value.
- WHEN the screen renders the remaining fields, THE SYSTEM SHALL show "Hồi hướng
  cho" (dedicate to), "Chùa nhận cúng dường" (receiving temple), and the
  commitment note ("100% chuyển thẳng đến chùa · có biên nhận công khai").
- WHEN the user taps the payment button, THE SYSTEM SHALL start payment and show
  a loading state, then navigate to the Receipt screen on success.

### Receipt

- WHEN the Receipt screen loads, THE SYSTEM SHALL show "Đèn đã được thắp" + a
  dedication kệ, and a table: Số tiền, Nơi nhận, Hồi hướng cho, Thời gian, Mã
  biên nhận (e.g. IL-2609-4471).
- WHEN the screen renders the confirmation, THE SYSTEM SHALL show "Chùa đã xác
  nhận · biên nhận công khai trong sổ công đức".
- WHEN the user taps "Lưu ảnh", THE SYSTEM SHALL save the receipt as an image.
- WHEN the user taps "Về trang chủ", THE SYSTEM SHALL clear the stack and return
  to Home.

## Out of scope (this feature boundary, not backend work)

- The Temple "Cúng dường" and Profile "Công đức" entries that navigate here —
  owned by those features.
- The actual payment provider / gateway integration details (assumed a shared
  concern); this feature calls it and renders the result.
